ポリシーの読み込み（JSON インポート）

アプリの JSON 形式（sample-policies-for-review.json と同じ形式）のファイルを読み込んで、ポリシーを登録します。

  1. 左サイドバーの「ポリシーを読み込む」ボタンをクリックします。
  2. ファイル選択ダイアログが開くので、JSON ファイルを選択します。
  3. 変更記録の入力画面が表示されます。以下の項目を入力してください:
    • 変更者（必須）: 誰がこのインポートを実施したかを記録します。
    • 変更理由（必須）: なぜこのインポートを行ったかの理由を記録します。
  4. 「読み込み確定」ボタンをクリックすると、ポリシーが一覧に追加されます。

読み込めるのは、アプリの JSON 形式（id・name・state・assignments・conditions・accessControls を持つポリシー）を配列にしたファイルです。ポリシーが 1 件の場合も、配列（[ ]）で囲んでください。単一のポリシーだけの JSON は、読み込みエラーになります。Microsoft Entra 管理センターや Microsoft Graph の形式（displayName・grantControls など）は、アプリの形式に変換してから読み込んでください。

ポリシーの手動登録

JSON ファイルがない場合でも、手動でポリシーを作成・登録できます。「+ 新規登録」ボタンから以下の項目を入力してください。

基本情報

  • ポリシー名（必須）: ポリシーを識別するための名前を入力します。
  • ポリシーの有効化: オン / レポートのみ / オフ のいずれかを選択します。

割り当て

  • ユーザー: 対象に含めるユーザー、および除外するユーザーを指定します。
  • ロール: 対象に含めるロール、および除外するロールを指定します。
  • グループ: 対象に含めるグループ、および除外するグループを指定します。

対象リソース

  • アプリケーション: 対象に含めるアプリケーション、および除外するアプリケーションを指定します。

条件

  • デバイスプラットフォーム: Windows, iOS, Android, macOS, Linux など
  • クライアントアプリ: ブラウザー、モバイルアプリ/デスクトップ、レガシー認証クライアント
  • 場所: ネームドロケーション（名前付きの場所）による条件
  • ユーザーリスク: ユーザーアカウントの危険度レベル
  • サインインリスク: サインイン試行の危険度レベル
  • デバイスフィルター: デバイスの属性に基づくフィルタリング条件

アクセス制御

  • ブロック: アクセスを拒否します。
  • 許可: 以下の条件付きでアクセスを許可します。
    • 多要素認証（MFA）を要求
    • 認証強度が必要
    • デバイスが準拠としてマーク済み
    • Microsoft Entra ハイブリッド参加済みデバイスが必要
    • 承認されたクライアント アプリを要求
    • アプリの保護ポリシーを必須にする
    • パスワードの変更を必須とする
    • 利用規約が必須

セッション

  • 監視のみ: アクセスを許可しつつ、アクティビティを監視します。
  • ダウンロードブロック: ファイルのダウンロードを制限します。
  • サインイン頻度: 再認証を要求する間隔を設定します。
  • 永続的ブラウザーセッション: ブラウザーを閉じてもセッションを維持するかどうかを設定します。

ポリシーの編集

登録済みのポリシーを編集して、設定内容を変更できます。

  1. ポリシー一覧で、編集したいポリシーの行にある「編集」ボタンをクリックします。
  2. フォーム上で各項目を変更します。
  3. 「保存」ボタンをクリックして変更を確定します。

変更を保存すると、変更内容は変更履歴に記録されます。画面からの登録・編集・削除では、変更者の欄は「手動編集」などの操作名になり、個人名は記録されません。変更者と理由を残したい場合は、JSON ファイルの読み込みで更新してください（読み込み時に変更者と理由の入力が必須です）。

ポリシーの削除

不要になったポリシーを一覧から削除できます。

  1. ポリシー一覧で、削除したいポリシーの行にある「削除」ボタンをクリックします。
  2. 確認のダイアログが表示されるので、削除を確定します。

削除は元に戻せません。必要に応じて、事前に JSON エクスポートでバックアップを取ってから削除してください。

ポリシーのコピー

既存のポリシーをベースに新しいポリシーを作成する場合、コピー機能が便利です。

  1. ポリシー一覧で、コピー元のポリシーの行にある「コピー」ボタンをクリックします。
  2. 「ポリシーのコピー（内容を変更して保存）」の画面が開き、ポリシー名が「元の名前 (コピー)」になります。
  3. 必要に応じて内容を変更し、「保存」をクリックすると、新しいポリシーとして一覧に追加されます。

JSON エクスポート

登録済みのポリシーを JSON ファイルとしてエクスポートできます。一覧での選択に関係なく、登録済みのすべてのポリシーが書き出されます。

  1. ポリシー管理画面の上部にある「JSON エクスポート」ボタンをクリックします。
  2. 保存先とファイル名を指定して JSON ファイルを保存します。

エクスポートした JSON は、他の環境での参照やバックアップとして利用できます。また、別の CA Policy Analyzer インスタンスに再インポートすることも可能です。

この機能は Trial・Standard・Pro のどのプランでも利用できます。

Loading Policies (JSON Import)

Import a JSON file in the app's JSON format (the same format as sample-policies-for-review.json) to register your policies.

  1. Click the "Load Policies" button in the left sidebar.
  2. A file selection dialog will open. Select your JSON file.
  3. A change record input screen will appear. Fill in the following fields:
    • Changed By (required): Records who performed this import.
    • Change Reason (required): Records the reason for this import.
  4. Click the "Confirm Load" button to add the policies to the list.

You can import only a file that contains an array of policies in the app's JSON format (each policy has id, name, state, assignments, conditions, and accessControls). Enclose even a single policy in an array ([ ]). A JSON file that contains only a single policy object causes a load error. Convert the Microsoft Entra admin center or Microsoft Graph format (displayName, grantControls, and so on) to the app's format before you import it.

Manual Policy Registration

Even without a JSON file, you can create and register policies manually. Click the "+ New Policy" button and fill in the following fields.

Basic Information

  • Policy Name (required): Enter a name to identify the policy.
  • Policy Enabled: Select one of On / Report-only / Off.

Assignments

  • Users: Specify users to include and exclude from the policy scope.
  • Roles: Specify roles to include and exclude from the policy scope.
  • Groups: Specify groups to include and exclude from the policy scope.

Target Resources

  • Applications: Specify applications to include and exclude from the policy scope.

Conditions

  • Device Platforms: Windows, iOS, Android, macOS, Linux, etc.
  • Client Apps: Browser, mobile apps/desktop clients, legacy authentication clients
  • Locations: Conditions based on named locations
  • User Risk: Risk level of the user account
  • Sign-in Risk: Risk level of the sign-in attempt
  • Device Filter: Filtering conditions based on device attributes

Access Controls

  • Block: Deny access entirely.
  • Grant: Allow access with the following conditions:
    • Require multi-factor authentication (MFA)
    • Require authentication strength
    • Require device to be marked as compliant
    • Require Microsoft Entra hybrid joined device
    • Require approved client app
    • Require app protection policy
    • Require password change
    • Require terms of use

Session

  • Monitor Only: Allow access while monitoring activity.
  • Block Download: Restrict file downloads.
  • Sign-in Frequency: Set the interval for requiring re-authentication.
  • Persistent Browser Session: Configure whether sessions persist after closing the browser.

Editing Policies

You can edit registered policies to modify their configuration.

  1. In the policy list, click the "Edit" button in the row of the policy you want to edit.
  2. Modify the desired fields in the form.
  3. Click the "Save" button to confirm your changes.

When you save changes, they are recorded in the change history. For additions, edits and deletions made on screen, the "changed by" field shows an operation name such as "Manual Edit" rather than a person's name. If you need to record who made a change and why, update the policies by loading a JSON file instead (the person and reason are required when loading).

Deleting Policies

You can remove policies that are no longer needed from the list.

  1. In the policy list, click the "Delete" button in the row of the policy you want to delete.
  2. A confirmation dialog will appear. Confirm the deletion in the dialog.

Deletion cannot be undone. We recommend creating a backup via JSON export before deleting any policy.

Copying Policies

The copy feature is useful when you want to create a new policy based on an existing one.

  1. In the policy list, click the "Copy" button in the row of the source policy.
  2. The "Copy Policy (modify and save)" screen opens, and the policy name is set to "Original Name (Copy)".
  3. Modify the contents as needed and click "Save" to add it to the list as a new policy.

JSON Export

You can export registered policies as JSON files. All registered policies are exported, regardless of any selection in the list.

  1. Click the "JSON Export" button at the top of the Policy Management screen.
  2. Specify the destination and file name to save the JSON file.

Exported JSON files can be used for reference in other environments or as backups. They can also be re-imported into another CA Policy Analyzer instance.

This feature is available on every plan: Trial, Standard and Pro.
