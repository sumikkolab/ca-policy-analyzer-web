変更履歴とは

このアプリでのポリシーの読み込み・登録・編集・削除を、時系列で残す機能です。

JSON ファイルを読み込むときは、変更者と変更理由の入力が必須です。入力した内容が、日時・元のファイル名・追加／削除／変更されたポリシーと項目ごとの新旧の値とあわせて記録されるため、「誰が」「いつ」「なぜ」「何を」変更したかを後から確認できます。画面からの登録・編集・削除は、変更者の欄が「手動編集」などの操作名で自動的に記録されます。

この変更履歴は、アプリの中で行った操作の記録です。Entra ID テナントの監査ログではないため、Entra 管理センターなどで直接行った変更は記録されません。

一覧表示

「変更履歴」タブを開くと、すべての変更が時系列で一覧表示されます。各エントリには以下の情報が表示されます:

項目 説明
日時 変更が行われた日時
変更者 読み込み時に入力した変更者（画面での操作は「手動編集」などの操作名）
変更理由 変更の目的や背景
追加・削除・変更の件数 追加（+）・削除（-）・変更（~）されたポリシーの件数を示すバッジ。0 件の種類は表示されません。
ポリシー数 その変更の後のポリシーの総数（JSON の読み込みでは、読み込んだポリシーの総数）。影響を受けた件数ではありません。

ファイル名は一覧には表示されません。詳細画面にだけ表示されます。

変更の詳細表示

一覧からエントリをクリックすると、変更の詳細が表示されます。詳細画面には、日時・変更者・理由・ファイル（読み込んだ JSON ファイル名）・ポリシー数のほか、以下が表示されます:

  • 追加されたポリシー: 新しく追加されたポリシーの一覧
  • 削除されたポリシー: 削除されたポリシーの一覧
  • 変更されたポリシー: 変更されたポリシーの一覧（フィールド単位の差分付き）

差分の読み方

変更されたポリシーについては、「フィールド」「変更前」「変更後」の列で、フィールドごとの差分が表示されます。以下は差分表示の例です:

フィールド 変更前 変更後
AccessControls.Requirements Mfa Mfa, CompliantDevice

ポリシーは、変更の種類によって次の 4 つに分類されます:

  • 追加: 新しく追加されたポリシー
  • 削除: 削除されたポリシー
  • 変更: 設定が変更されたポリシー（上記のフィールドごとの差分が表示されます）
  • 変更なし: 設定に変更がないポリシー

変更履歴の活用

変更履歴は設計書エクスポート（Excel / PDF）に含まれます。Excel では「変更管理記録」シートに出力され、PDF では変更履歴がある場合に「変更管理記録」ページが追加されます。監査対応時にそのまま提出資料として活用できます。

変更履歴を活用することで、以下のような場面で役立ちます:

  • セキュリティ監査への対応: いつ・誰が・なぜ変更したかを証跡として提出
  • トラブルシューティング: 問題が発生した時点の変更内容を特定
  • チーム内の情報共有: ポリシー変更の経緯をチームメンバーと共有

Chapter 7: Change History

CA Policy Analyzer User Manual

What is Change History?

Change History keeps a chronological record of policy loads, additions, edits and deletions made in this app.

When you load a JSON file, you must enter who is making the change and why. That information is saved together with the date and time, the source file name, the added, removed and modified policies, and the old and new value of each changed setting, so you can later see who changed what, when and why. Additions, edits and deletions made on screen are recorded automatically, with an operation name such as "Manual Edit" in the "changed by" field.

This history only covers operations performed in the app. It is not your Entra ID tenant's audit log, so changes made directly in the Entra admin center or elsewhere are not recorded.

List View

Opening the "Change Log" tab displays all changes in chronological order. Each entry shows the following information:

Field Description
Date/Time When the change was made
Changed By The person entered when loading the file (for on-screen operations, an operation name such as "Manual Edit")
Reason Purpose or background of the change
Added / Removed / Modified counts Badges showing the number of policies added (+), removed (-), and modified (~). A type with zero policies is not shown.
Policy Count Total number of policies after the change (for a JSON load, the total number of policies loaded). It is not the number of policies affected.

The file name is not shown in the list. It appears only on the detail screen.

Change Details

Click an entry in the list to view the change details. In addition to the date/time, changed by, reason, file (the loaded JSON file name), and policy count, the detail screen shows:

  • Added Policies: List of newly added policies
  • Removed Policies: List of removed policies
  • Modified Policies: List of modified policies (with field-level diffs)

Reading the Diff

For modified policies, a field-by-field diff is displayed in the "Field", "Before" and "After" columns. Here is an example:

Field Before After
AccessControls.Requirements Mfa Mfa, CompliantDevice

Each policy is classified into one of the following four types:

  • Added: Policies that were newly added
  • Removed: Policies that were deleted
  • Modified: Policies whose settings changed (the field-by-field diff above is shown)
  • Unchanged: Policies whose settings did not change

Utilizing Change History

Change history is included in the design document export. In Excel, it appears in the "Change Log" sheet. In the PDF, a "Change Log" page is added when change history exists. It can be used as-is as audit submission material.

Change history is useful in the following scenarios:

  • Security audit response: Submit evidence of who changed what, when, and why
  • Troubleshooting: Identify the changes made at the time a problem occurred
  • Team communication: Share the history of policy changes with team members
