シミュレーションとは PRO

シミュレーション機能は、「もし〇〇なユーザーが△△にアクセスしたら？」という仮定のシナリオを検証するための機能です。

登録済みの条件付きアクセスポリシーに対して、仮想のアクセス条件（ユーザー、プラットフォーム〔OS〕、場所など）を入力し、その条件下でアクセスが BLOCK（ブロック） されるのか、ALLOW（許可） されるのかの判定結果を確認できます。

これにより、ポリシーを実環境に適用する前に、意図した通りに動作するかを安全に検証できます。

サインインリスク・ユーザーリスクとデバイスの準拠状態は入力できません。リスクを条件にしたポリシーは「不適用」と判定されます。実際のサインインへの影響は測定しないため、ギャップ分析の詳細に示される KQL の例で確認してください。

シナリオの入力

シミュレーション画面で、以下のアクセス条件を設定します。

入力項目 説明
ユーザー アクセスを試みるユーザー名を入力します。
グループ ユーザーが所属するグループ名を入力します。
ターゲット リソース アクセス先のアプリケーション名を入力します。
デバイス プラットフォーム Windows, iOS, Android, macOS, Linux から選択します。
クライアント アプリ ブラウザー、モバイル アプリとデスクトップ、Exchange ActiveSync、その他 (レガシー) から選択します。
場所 事前に登録したネームドロケーション（名前付きの場所）を選択します。

ユーザー、グループ、ターゲット リソース、場所の入力欄は、フリーテキスト入力に対応しています。テキストを入力して Enter キーを押すと項目が追加されます。ユーザーは 1 人だけ指定します。複数入力しても、評価に使われるのは最初の 1 件だけです。グループ、ターゲット リソース、場所は、複数指定できます。デバイス プラットフォームとクライアント アプリは、一覧から選択します（複数選択できます）。

判定結果の読み方

シミュレーションを実行すると、以下の情報が表示されます。

最終判定

画面上部に最終的なアクセス判定が大きく表示されます。

  • ブロック (アクセス拒否): いずれかのポリシーによりアクセスがブロックされます。
  • 許可 (アクセス可能): すべてのポリシーの条件を満たし、アクセスが許可されます。

要求コントロール

アクセスが許可される場合に必要となる条件（多要素認証、準拠デバイスなど）が一覧で表示されます。

評価サマリ

項目 説明
評価対象 判定対象となったポリシーの総数です。
適用 入力した条件に一致し、実際に適用されたポリシーの数です。
不適用 入力した条件に一致せず、適用されなかったポリシーの数です。
無効 無効状態に設定されているため、評価から除外されたポリシーの数です。

適用ポリシーの根拠

シミュレーション結果には、各ポリシーの評価理由が詳しく表示されます。

「適用ポリシー」セクション

条件に一致して適用されたポリシーの一覧が表示されます。各ポリシーについて、どの条件が一致したかの詳細を確認できます。

「スキップされたポリシー」セクション

適用されなかったポリシーの一覧が表示されます。条件に一致しなかったポリシーに加えて、無効状態のポリシーも含まれます。

  • 条件不一致でスキップ: どの条件が一致しなかったかの理由がポリシーごとに表示されます。
  • 無効 (Disabled) ポリシー: 無効状態のため評価されなかったポリシーの名前が表示されます。

これらの情報により、意図しないブロックや許可が発生した場合の原因を特定し、ポリシーの設定を改善できます。

比較モード PRO

比較モードでは、2〜4 つのシナリオを並べて比較できます。異なるアクセス条件を設定した複数のシナリオを横並びで表示し、ポリシーの評価結果の違いを一目で把握できます。

  1. シミュレーション画面で「比較モード」を有効にします。
  2. 各シナリオに異なるアクセス条件を設定します。
  3. 「比較実行」ボタンをクリックすると、すべてのシナリオが同時に評価されます。
  4. 結果が横並びの表形式で表示されます。

比較結果の例

ポリシー名 シナリオ 1 シナリオ 2
MFA 必須ポリシー 許可 許可
社外アクセスブロック ブロック 不適用
レガシー認証ブロック 不適用 ブロック

この比較により、条件の違いがどのポリシーに影響するかを明確に把握できます。

シミュレーションは Pro プランで利用できます（単一のシナリオも比較モードも）。

Chapter 3: Simulation

CA Policy Analyzer User Manual

What is Simulation? PRO

The Simulation feature allows you to test hypothetical scenarios such as "What happens if a specific user tries to access a particular application?"

By entering virtual access conditions (user, platform (OS), location, etc.) against your registered Conditional Access policies, you can verify whether access would be BLOCKED or ALLOWED under those conditions.

Sign-in risk, user risk and device compliance cannot be entered. Policies that use risk as a condition are reported as "Not applied." The simulation does not measure the impact on real sign-ins; use the sample KQL queries in the Gap Analysis details for that.

This allows you to safely verify that your policies work as intended before deploying them to a production environment.

Entering a Scenario

On the Simulation screen, configure the following access conditions.

Input Field Description
User Enter the name of the user attempting access.
Group Enter the group(s) the user belongs to.
Target Resource Enter the name of the application being accessed.
Device Platform Select from Windows, iOS, Android, macOS, or Linux.
Client Application Select from Browser, Mobile apps and desktop, Exchange ActiveSync, or Other (Legacy).
Location Select from pre-registered named locations.

The User, Group, Target Resource, and Location fields support free-text entry. Type your text and press Enter to add an item. Specify only one user: if you enter several, only the first one is used in the evaluation. You can specify multiple values for Group, Target Resource and Location. Device Platform and Client Application accept selection from a list only (you can select several).

Reading the Results

After running a simulation, the following information is displayed.

Final Verdict

The final access decision is prominently displayed at the top of the screen.

  • Block (Access Denied): Access is blocked by one or more policies.
  • Allow (Access Granted): All policy conditions are met, and access is permitted.

Required Controls

When access is allowed, the required conditions (such as multi-factor authentication or a compliant device) are displayed in a list.

Evaluation Summary

Item Description
Evaluated The total number of policies that were evaluated.
Applied The number of policies whose conditions matched the input and were applied.
Not Applied The number of policies whose conditions did not match the input.
Disabled The number of policies excluded from evaluation because they are in a disabled state.

Policy Application Details

The simulation results include detailed evaluation reasons for each policy.

"Applied Policies" Section

Lists the policies that matched the conditions and were applied. For each policy, you can review the details of which conditions were matched.

"Skipped Policies" Section

Lists the policies that were not applied. This includes policies whose conditions did not match, as well as disabled policies.

  • Skipped due to condition mismatch: For each policy, the reason why the conditions did not match is displayed.
  • Disabled Policy: The names of policies that were not evaluated because they are disabled are displayed.

This information helps you identify the cause of unintended blocks or grants and improve your policy configuration.

Comparison Mode PRO

Comparison Mode lets you compare two to four scenarios side by side. You can set different access conditions for each scenario and view the policy evaluation results in a side-by-side format, making it easy to spot differences at a glance.

  1. Enable "Compare Mode" on the Simulation screen.
  2. Set different access conditions for each scenario.
  3. Click the "Run Comparison" button to evaluate all scenarios simultaneously.
  4. Results are displayed in a side-by-side table format.

Comparison Results Example

Policy Name Scenario 1 Scenario 2
MFA Required Policy Allow Allow
External Access Block Block Not Applied
Legacy Auth Block Not Applied Block

This comparison makes it clear which policies are affected by different conditions.

Simulation is available with the Pro plan (both single scenarios and comparison mode).
